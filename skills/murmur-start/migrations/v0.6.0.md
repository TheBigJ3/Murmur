# Migration to v0.6.0

## Summary

Load graphs can check the server's current state with `unlocks` and `locks`, run role
personas with a fixed `count`, pool group and starting flags, gate work on
`@in:<group>`, create accounts that grow
the pool, give accounts roles with `joins`, and pass values between users through a
shared board. The health endpoint reports whether rate limits are relaxed. The mapping
prompt's update run adopts all of this and adds `.murmur/pool.grown*.json` to
`.gitignore`. It also asks you whether to add a dev-only switch that turns off every rate
limit, and adds a dev-only grant-role endpoint only when the app can grant a role no
other way. Declining the switch changes nothing. These are part of the update run, not
steps you do by hand. Graphs from earlier versions stay valid.
